# Configuration (v1 - Legacy)

:::caution Deprecated Configuration Format
Configuration specification `version: 1` has been deprecated since **v0.6.0**.

Modern versions of `hypr-input-switcher` (v0.6.0+) use **Configuration v2**, which introduces multi-engine input method support, unified `profile` abstractions, window title matching, regex rules, and layer-shell overlay support.

👉 For current setups, please refer to the [**Configuration v2 Guide**](./v2).
:::

## Overview

The `version: 1` configuration was the initial format shipped with early releases of Hypr Input Switcher. It supported basic class-to-input-method mapping with simple notification toggles.

### Example v1 Configuration

```yaml
version: 1

client_rules:
  firefox: chinese
  google-chrome: chinese
  kitty: english
  code: english

notifications:
  enabled: true
  duration: 2000
  show_on_switch: true
```

## Limitations of v1

The v1 format had several architectural constraints:
1. **No Window Title Matching**: Rules were strictly keyed by application `class`. Windows could not be differentiated by document title or URL.
2. **No Regular Expression Support**: Rules required exact class name matches without regex flexibility.
3. **No Layer-Shell Overlay Support**: Desktop overlays (such as Omarchy launchers, calculators, or notification widgets) could not be intercepted.
4. **Hardcoded Engine Assumptions**: The daemon assumed English was strictly the inactive controller state and non-English was solely handled by Rime schemas.

## Upgrading from v1 to v2

`hypr-input-switcher` provides built-in migration assistance. When an existing `version: 1` configuration is detected, the daemon automatically upgrades the file or converts the rules into v2 format.

### Automatic Migration
The internal migration utility transforms v1 client rules into v2 rule objects:

```yaml
# Before (v1)
client_rules:
  firefox: chinese
  code: english

# After (v2)
client_rules:
  - class: firefox
    input_method: chinese
  - class: code
    input_method: english
```

For full details on v2 features and syntax, see the [**Configuration v2 Guide**](./v2).
